cc-safety-net
Growth review 14 September 2026 Baseline v2.4.1

Shipping hard,
growing flat.

Twenty-three releases in five weeks moved the star count by eighty-six. The product is not the problem. The project stopped explaining why it exists, is stale in every registry its host CLIs point to, and appears in zero search results for the problem it solves.

01 — Diagnosis

Effort and attention came apart in February

Sixty percent of all stars arrived in the first six weeks, on a wave nobody has identified and nobody has repeated. Since then the release count and the star count have moved independently. Release days add between zero and six stars.

Both charts share a monthly axis and a single scale each. September is partial, to the 14th, and is drawn in the muted tone with its value labelled. Source: 1,539 stargazer timestamps and 47 releases from the GitHub API.

What actually caused the launch wave

The ten best days all fall between 26 December 2025 and 8 January 2026. Two of the five peaks now have an identified cause, and both are instructive.

Three things follow. The largest identified driver was one blog post by one writer, never contacted since — a warm contact, not a cold pitch. The one Hacker News attempt landed on the lowest-traffic day of the year and returned 68 stars, so that channel has effectively never been tested. And the two biggest days are still unexplained: GitHub Trending was ruled out against a dated archive, and the 110-then-73 decay looks like a newsletter placement. GitHub's traffic referrers for that week would probably name it.

The detail that matters most: the README of that era carried an origin story — Claude Code had silently wiped out hours of work, and soft rules cannot replace hard technical constraints. That is the framing Korben quoted. It is not in the README today.

02 — Priorities

Three moves, in this order

Ordered by expected value per hour of maintainer time. Everything in the full plan is downstream of these.

Put the argument back above the fold

A sourced “Why this exists” section was written on 31 August and deleted on 1 September. It carried the two claims no competitor can make. git show 6e0d788 recovers it.

Every other channel links back to this paragraph, so it cannot go second.

Run the registry sweep

Anthropic's community marketplace ships a build pinned to June: v1.0.6, two majors old, under the former repository name. Copilot CLI pre-registers two marketplaces and this is in neither. Three awesome-lists worth ~66,000 stars still carry the old name.

Mostly ten-minute fixes whose reach is a host's entire user base.

Occupy the problem in search

For “claude code deleted my files” and five sibling queries, the results are GitHub issues written by people it happened to. No product appears anywhere in roughly forty-five URLs.

The people typing these queries have the problem at that moment.

04 — The field

Category leader with a distribution problem

At 1,539 stars this is the largest single-purpose guard in open source, roughly five times the next one. The threat is not another guard. It is the host shipping its own.

Three differentiators worth defending. Deterministic semantic parsing that Anthropic's own docs admit their deny rules lack. Thirteen hosts, including native Windows and PowerShell, where the built-in sandbox is not supported. A published residual-risk registry no rival offers.

Narrative beat breadth. A rival hook guard created on 11 August reached roughly 1,980 stars in five weeks on a memorable name, a second-person README and Chinese-first docs. In the same window this project gained 86 stars while shipping 23 releases.

07 — Measurement

Nothing here can be judged today

There is no telemetry by design, no analytics on the docs site, and no snapshot of GitHub traffic, which expires every fourteen days. A daily snapshot Action is a one-hour job and it gates the credibility of everything above.

10 — Method

How this was researched, and where it is thin

Fifteen dimensions were researched in parallel: positioning, onboarding, competitors, marketplaces, content, search, product loops, partnerships, monetisation, community, narrative, international, metrics, user voice and risk. All fifteen returned findings, roughly 250 in total, each with evidence and at least one source. Sources were the GitHub API, the npm registry, host CLI documentation and changelogs, the repository and its history, and the public web.

Known limits. The adversarial verification pass designed to fact-check every finding did not complete, so findings carry their researcher's confidence rating rather than an independent second read; the highest-stakes numbers here were re-checked by hand. The documentation site and the npm downloads API were unreachable from the research environment, so docs facts come from the public source repository and downloads from the registry search endpoint. GitHub traffic insights need push access and were not readable. Every route to Hacker News was blocked, so the score and comments on the project's one Show HN are unread and its dates were reconstructed indirectly; two of the five launch-peak days remain unexplained.
